## Initial interpretation

The first `0x5c` bytes decode as the generic Pia advertisement header. The final 40 bytes encode
the four-character value `1272` and length `4`, in the same position used for Scarlet/Violet Link
Trade codes. No boss, Tera type, difficulty, or seed is present in this LDN advertisement.

This establishes the first differential result: a Tera Raid uses `scene_id = 7` and four participant
slots, whereas the existing Link Trade implementation uses `scene_id = 4` and two slots.

## Join-probe result

A constrained PokéLDN client associated successfully to a separate scene-7 raid lobby, received a
Session Update that seated it as station 1, exchanged clone-clock and reliable-stream setup, and
sent the host's 46 identity records back on the joiner stream. It also acknowledged reliable data
and opened the existing game channel.

The host acknowledged the transport traffic but did not issue the expected port-2 activity
announcement during the 12-second post-setup window. The next unknown is therefore the
Scarlet/Violet application-level join identity or activity-join state, not the LDN/Pia transport.

## Fake-host discovery result

The existing Scarlet/Violet host was extended with configurable `--scene-id` and
`--max-participants` arguments. Replaying this capture's full advertisement with scene `7`,
capacity `4`, and its captured game-data suffix caused the retail Switch to discover and associate
to the ESP32 fake host. The Switch then retried its Pia Session join because the generic Link Trade
host's session replies are not yet in the retail Tera Raid host layout. Discovery and LDN association
are therefore proven; the next target is a raid-compatible Session Update and application handshake.

## Code differential

A second real local Tera Raid lobby, generated by the game with code `3000`, was captured on channel
11. Its advertisement is identical to capture 001 except for the expected code-dependent fields:

- the Pia header's masked user-password bytes change from `d4992edf` (`1272`) to `d69b29dd`
  (`3000`);
- the game-data prefix changes from ASCII `1272` to ASCII `3000`.

The trailing bytes `3c756404000000` are unchanged. In particular, the three bytes `3c7564` are not
the generated local Link Code. A fake host must advertise the same generated code that its retail
guest enters, using `sv.build_advertise_data(code=CODE)` (or the captured 40-byte suffix).
